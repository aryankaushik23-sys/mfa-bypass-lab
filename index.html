Live Attack Demonstrations

Critical — CVSS 9.0

Module 1 — OTP Interception via AiTM Phishing

Evilginx3 reverse proxy sits between the victim browser and Keycloak IdP. Live TOTP codes and session cookies are intercepted and replayed — proving authenticated access without ever knowing the OTP directly.

T1111 Evilginx3 Keycloak Wireshark TOTP
Terminal demo — AiTM session capture (recording coming soon)
Demo recording will be added after Evilginx3 setup is complete.
Mitigation: FIDO2/WebAuthn enabled as required authenticator in Keycloak. Credential is cryptographically bound to the legitimate origin — a proxy at any other domain cannot satisfy the WebAuthn ceremony. This attack class is eliminated entirely.
High — CVSS 7.5

Module 2 — MFA Fatigue via Push Notification Bombing

Python script sends 20 successive push authentication requests to a test Authentik account using valid credentials. No MFA bypass, no malware — a single fatigued approval grants full authenticated access. Real-world example: Uber breach 2022.

T1621 Authentik Python Burp Suite Push MFA
Terminal demo — push flood script running live
Mitigation: Number matching enforced — user must type a displayed code, preventing blind approval. Rate limiting configured at 5 attempts per account per 10-minute window. Push context enriched with app name, source IP, and location.
High — CVSS 7.1

Module 3 — SMS OTP Interception via SIM-Swap

Local Asterisk PBX and two softphone clients simulate number hijacking. The SMS OTP is redirected to the attacker-controlled number — authentication succeeds with zero device access, zero malware, and no password knowledge beyond the username.

T1111 Asterisk pyotp VoIP SS7
Terminal demo — SIM-swap OTP redirect live
Mitigation: SMS MFA removed from all Keycloak authentication flows per NIST SP 800-63B §5.2.10. All users migrated to TOTP (RFC 6238) minimum, FIDO2 recommended. SS7 protocol has no authentication — the only fix is to stop using SMS.

How The Lab Works

  1. Keycloak identity provider deployed in Docker on Kali Linux — acts as the victim login system accessible at localhost:8080
  2. Authentik deployed in a separate Docker stack for push MFA testing — accessible at localhost:9000
  3. Attacker tools (Evilginx3, Python scripts) run on the same isolated Kali machine — no external network exposure
  4. Each attack demonstrated against real running services — not simulated or mocked output
  5. Evidence captured: Wireshark packet captures, JSON attack logs, terminal session recordings
  6. Mitigations implemented directly in Keycloak and Authentik admin configuration
  7. All findings documented in pentest report format with CVSS v3 scores and MITRE ATT&CK mapping
